# 01. ローカル開発環境の構築

## 1. 必要なもの

| ツール | バージョン | 用途 | 備考 |
|---|---|---|---|
| macOS | 13 以降 | アプリの実行・ビルド | フロントエンドと `s3drive-core` の開発・テストは Linux でも行える |
| Xcode Command Line Tools | 最新 | Rust のリンク、`codesign` | Xcode 本体は不要 |
| Rust | stable | バックエンド | `rust-toolchain.toml` で指定。rustup で導入する |
| Node.js | 26 | フロントエンド | `.node-version` で指定 |
| pnpm | 12 | パッケージ管理 | `package.json` の `packageManager` で指定 |
| Docker | — | 結合テスト・E2E の S3 モック（moto） | Docker Desktop、OrbStack、colima などのいずれか |
| GitHub CLI（任意） | — | ワークフローの実行・リリースの確認 | `gh` |

## 2. ツールの導入

### 2.1 Xcode Command Line Tools

```bash
xcode-select --install
```

### 2.2 Rust

[rustup](https://rustup.rs/) を導入する。リポジトリで初めて `cargo` を実行すると、`rust-toolchain.toml` に従って stable のツールチェーンと、コンポーネント（rustfmt、clippy）、ターゲット（`aarch64-apple-darwin`、`x86_64-apple-darwin`）が自動で導入される。

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

### 2.3 Node.js と pnpm

Node.js は `.node-version`（26）を読み取れるバージョン管理ツール（fnm、mise、nodenv など）で導入する。例として fnm の場合:

```bash
brew install fnm
```

```bash
fnm install
```

pnpm は 12 系を導入する。リポジトリ内で実行すると、`packageManager` に書かれたバージョン（例: `pnpm@12.6.0`）が自動で取得されて使われる。

```bash
npm install -g pnpm@12
```

### 2.4 Docker

Docker Desktop などを導入し、`docker compose` が使えることを確認する。

```bash
docker compose version
```

## 3. リポジトリの準備

```bash
git clone https://github.com/Sh1gekicks/s3driveapp.git
```

```bash
cd s3driveapp && pnpm install
```

- `pnpm-workspace.yaml` の設定により、公開から 1 日未満のバージョンはインストールされない。また、依存パッケージのビルドスクリプト（postinstall など）は許可したもの以外は実行されない。新しい依存でスクリプトが必要な場合は、`allowBuilds` に理由をコメントして追加する。
- Rust の依存は、初回の `cargo build`（または `pnpm tauri dev`）で取得・ビルドされる。初回は数分かかる。

## 4. アプリの起動

開発の目的に応じて、次のいずれかで起動する。

| 方法 | コマンド | 接続先 | 用途 |
|---|---|---|---|
| モックバックエンド（ブラウザ） | `pnpm dev:mock` | なし（メモリ上のモック） | 画面の開発。Rust のビルドが不要で速い |
| アプリ（moto） | `S3DRIVE_TEST_ENDPOINT=... pnpm tauri dev` | moto | AWS を使わずに一連の操作を確認する |
| アプリ（AWS） | `pnpm tauri dev` | 実際の AWS | 実際のバケットで確認する |

### 4.1 モックバックエンド（ブラウザ）

```bash
pnpm dev:mock
```

http://localhost:1420/ を開く。URL のクエリで初期状態を切り替えられる。

| URL | 状態 |
|---|---|
| `http://localhost:1420/` | サインイン済み・接続あり |
| `http://localhost:1420/?signedOut=1` | サインイン前 |
| `http://localhost:1420/?empty=1` | 接続なし |

### 4.2 アプリ（実際の AWS）

```bash
pnpm tauri dev
```

- Vite の開発サーバー（ポート 1420）とアプリが起動し、フロントエンドの変更はホットリロードされる。Rust の変更は保存すると再ビルドされる。
- Google の OAuth クライアント（`S3DRIVE_GOOGLE_CLIENT_ID`）を設定していない開発ビルドは、固定のテスト用セッションでサインインする。Google のサインインを確かめる場合は §5 を参照。
- 開発ビルドは、設定・データベースの保存先とキーチェーンのサービス名にバンドル ID + `.dev` を使い、リリース版のデータとは分かれる（`~/Library/Application Support/io.github.sh1gekicks.s3drive.dev/`）。

### 4.3 アプリ（moto）

AWS の代わりに moto（S3 などのモック）に接続する。

```bash
docker compose -f docker-compose.test.yml up -d
```

```bash
S3DRIVE_TEST_ENDPOINT=http://localhost:5000 pnpm tauri dev
```

- `S3DRIVE_TEST_ENDPOINT` は開発ビルドと E2E ビルドでのみ有効で、リリースビルドでは無視される。
- moto は起動のたびに空になる。バケットは curl などで作成する（[03 §2.3](03-test.md#23-e2e-テスト) のバケットの作成手順を参照）。接続の登録では、アクセスキーとシークレットに任意の値（形式だけ正しいもの）を入力する。
- moto のイメージは 5.1 系（`motoserver/moto:5.1.22`）に固定している。5.2 系は `GetBucketVersioning` の応答が S3 と異なり、AWS SDK for Rust が解析できない。

## 5. Google サインインを使う場合（任意）

開発ビルドで実際の Google サインインを確かめる場合は、テスト用の OAuth クライアント（種類: デスクトップ アプリ）を GCP で作成し（[07 §2.1](../design/07-security.md#21-クライアントの登録)）、ビルド時の環境変数で渡す。値はビルド時に埋め込まれるため、変更したら再ビルドが必要になる（`build.rs` が環境変数の変化を検知して再ビルドする）。

```bash
export S3DRIVE_GOOGLE_CLIENT_ID=<クライアント ID>
export S3DRIVE_GOOGLE_CLIENT_SECRET=<クライアントシークレット>
pnpm tauri dev
```

| 環境変数 | 必須 | 内容 |
|---|---|---|
| `S3DRIVE_GOOGLE_CLIENT_ID` | ○ | OAuth クライアント ID。未設定なら開発ビルドは固定のセッションになる |
| `S3DRIVE_GOOGLE_CLIENT_SECRET` | ○ | OAuth クライアントシークレット |
| `S3DRIVE_ALLOWED_EMAILS` | — | 利用を許可するメールアドレス（カンマ区切り）。未設定なら制限しない |
| `S3DRIVE_ALLOWED_DOMAINS` | — | 利用を許可するドメイン（カンマ区切り）。未設定なら制限しない |

クライアントシークレットなどの値は、リポジトリにコミットしない（`.env` や `.env.local` は `.gitignore` 済み）。

## 6. 開発時の約束事

- **Rust の型を変えたら TypeScript の型を書き出す。** IPC で使う型は ts-rs で `src/lib/ipc/bindings` に生成している。Rust の型を変更したら `cargo test -p s3drive-core` を実行して書き出し、差分をコミットする（CI で差分がないことを確認している）。`src/lib/ipc/bindings` は手で編集しない。
- **IPC コマンドを追加したら権限も追加する。** `src-tauri/src/commands/mod.rs` の `app_commands!` にコマンドを追加すると、ビルド時に `src-tauri/permissions/autogenerated/` が生成される。使うウィンドウの `src-tauri/capabilities/*.json` に許可を追加する。
- **アクセスキー ID の形の文字列をコミットしない。** テスト用の値も `"AKIA"` と残りを分けて書く（CI の `audit` ジョブで検査する）。
- **書式と静的解析は Biome と rustfmt・clippy に従う。** コミット前に [03 §1](03-test.md#1-ローカルで-ci-と同じ検査を行う) の検査を実行する。
- **画面の見た目は `design-system/` を正とする。** 詳細は [02 UI 基盤](../design/02-ui-foundation.md) を参照。

## 7. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| moto に接続すると `403 Forbidden` が返る | macOS の AirPlay レシーバーが 5000 番ポートを使っている。「システム設定」→「一般」→「AirDrop と Handoff」で AirPlay レシーバーをオフにするか、moto を別のポートで起動し（例: `docker run -d --rm -p 5055:5000 motoserver/moto:5.1.22`）、`S3DRIVE_TEST_ENDPOINT` を合わせる |
| `pnpm tauri dev` で `Port 1420 is already in use` | 別の Vite（`pnpm dev:mock` など）が起動している。停止してから起動する |
| `pnpm install` で公開直後のバージョンを解決できない | `minimumReleaseAge`（1 日）による。1 日待つか、そのバージョンが必要な理由を確認する |
| 開発ビルドでキーチェーンの確認が何度も表示される | 開発ビルドは再ビルドのたびに署名が変わるため。「常に許可」を選ぶ |
| アプリの状態を初期化したい | アプリを終了し、`~/Library/Application Support/io.github.sh1gekicks.s3drive.dev/` を削除する。キーチェーンの項目は「キーチェーンアクセス」で `io.github.sh1gekicks.s3drive.dev` を検索して削除する |
| ログを確認したい | `~/Library/Logs/io.github.sh1gekicks.s3drive/`（開発ビルドもリリース版と同じフォルダ）。アプリの「ヘルプ」→「ログフォルダを開く」からも開ける |
